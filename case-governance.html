01 · Project Context

项目背景

在后台系统的设计过程中，不同页面之间存在大量重复的组件与细微的样式差异。一个按钮、一张表格、一个筛选区，会在十几个页面里被反复绘制，每一次都略有不同。 为了提升设计效率、降低与前端的沟通成本，使用 AI 工具辅助完成规范整理、Design Token 提取与组件库搭建，把原本零散的页面沉淀为一套可复用、可继承、并且能被 AI 继续调用的系统。

02 · Background

三大顽疾，拖垮一个后台

业务持续迭代多年后，系统在组件、Token 与规范三个层面同时失控。

随着 B 端管理员后台业务持续迭代，系统中逐渐暴露出三大顽疾，用户体验开始出现明显割裂。

// Pain 01
组件失控
同一功能场景出现多套组件变体，交互与视觉风格不一致，用户体验割裂。
// Pain 02
Token 混乱
颜色、字体、间距等设计 Token 存在大量硬编码与重复定义，暗黑模式适配几乎不可能。
// Pain 03
规范失效
设计规范文档与线上实现严重脱节，新页面开发时规范「形同虚设」，每个人都在凭感觉造轮子。
03 · The Cost

痛点聚焦：纯人工要 3 周

100+ 页面、上千组件实例，如果逐一走查、比对、修改，是一场注定遗漏与返工的消耗战。

更棘手的是，这个后台已上线运行 多年，页面数量超过 100+，组件实例数以千计。 若采用纯人工方式逐一走查、比对、修改，成本高得惊人：

设计师逐页截图比对
≥ 1 周
前端逐个组件替换 Token
≥ 1 周
设计与开发反复对齐修改
额外 1 周+
总计重复性劳动
≈ 3 周

且整个过程 极易遗漏与返工——人工比对千级实例，注意力难以持续，错误率随疲劳累积。

04 · The Bet

破局思路：引入 AI

能否用 AI 快速识别组件偏离与 Token 不一致，并自动生成 / 建议统一规范？

在调研了当前 AI 在 UI 分析、代码理解与批量重构辅助 方面的能力后，我提出一个设想： 能否用 AI 快速识别系统中的组件偏离、Token 不一致问题，并自动生成或建议统一规范？ 基于此，我选择这个 B 端管理员后台作为 首个试点项目，探索一条「AI 辅助规范治理」的工作路径。

01
// 为什么选这个后台
易学习，低风险
页面结构相对规整、组件复用率高，AI 易于学习规律；且后台对界面变更的敏感度低于 C 端，试错成本可控。
02
// 核心目标
3 周压缩到 7 天
将原本 3 周的手工治理周期压缩至 7 天内，同时输出一套可复用的 AI 治理流程。
05 · Workflow

工作流程

从典型页面分析到可复用的 Skill，整条「AI + 人工」协作路径分为 6 步，蓝色为 AI 环节、橙色为人工把关。

01

Feed to Claude

喂给 Claude 分析

挑选有代表性的典型页面，输入 Claude 进行分析。

02

Draft Specification

Claude 提炼规范草稿

输出初步设计规范草稿，覆盖颜色 / 字体 / 间距 / 组件。

03

Human Validation

人工交叉验证

设计师验证规范，分清真规范和历史错误，剔除遗留问题。

04

Figma Variables

Figma 创建变量 + 组件

Claude 在 Figma 创建颜色变量与组件框架，建立设计系统基础。

05

Design Refinement

设计师精修细节

优化间距、层级、文案等细节，把控最终视觉质量。

06

Skill Packaging

打包成 Skill

输出可复用的 Skill，沉淀为团队资产，可被其他 B 端项目直接复用。

06 · Design System

沉淀下来的设计系统

治理的最终产物——形成一套基于 Ant Design 扩展、面向「漏洞盒子管理后台」的完整设计系统 Token、UI 设计规范 Skill 等。
